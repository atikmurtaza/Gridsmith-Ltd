# E. Application and hosting security report

Architecture verified from source, not assumed. Evidence is static review plus the offline
assertions added in this phase; nothing was served by Hostinger in this phase.

## 1. What actually runs in production delivery

| Layer | Reality |
|---|---|
| Site | Next.js **static export** (`build:static`), plain files on Hostinger (LiteSpeed + hCDN). No Node runtime, no `app/api` (deleted by `build-static.mjs`), no Server Actions. |
| Headers | `next.config.ts` `headers()`/`redirects()` are **off** for static builds. The only delivered policy is the `.htaccess` generated by `lib/build/hostinger.ts`, emitted only for the staging origin today. |
| Forms | Browser `fetch` POST of JSON (`credentials: 'omit'`) to `NEXT_PUBLIC_LEAD_INTAKE_URL`, which `build-static.mjs` forces to the **isolated Preview** Supabase Edge function. Submit stays disabled until hydration (no pre-hydration GET leaks fields into a URL). |
| Intake | Supabase Edge `gs-lead-intake` (`verify_jwt=false`): exact Origin allowlist echoed with `Vary: Origin`; POST/OPTIONS only; JSON only; 64 KiB streamed cap; envelope whitelist; shared zod schema; honeypot `website` → silent 202; URL-in-name refused; per-isolate token bucket; `gs_intake_admit` global ceilings (5/15 min, 40/day, queue 50). |
| Database | RLS on all tables; 0004 revokes anon/authenticated grants (applied in Production); H4-B private schema RPCs SECURITY INVOKER, service_role only; **H4-B migration is Preview-only**. |
| Notifications | `gs-notification-worker` (`verify_jwt=true` + service-role/project-ref check) → Resend, plain text, idempotency key, recipient pinned to `contact@gridsmith.uk`, subject marked SYNTHETIC. |
| Analytics / cookies | None. One strictly necessary cookie `gs_consent` (365 days) set client-side only after "Got it". |

## 2. Delivered header policy (staging `.htaccess`)

`X-Robots-Tag noindex`; `X-Content-Type-Options nosniff`; `X-Frame-Options DENY`;
`Referrer-Policy strict-origin-when-cross-origin`; `Permissions-Policy` (camera, geolocation,
microphone, payment, usb, browsing-topics off); `Strict-Transport-Security max-age=31536000`;
CSP `default-src 'self'; base-uri 'self'; form-action 'self'; frame-ancestors 'none';
object-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https://cdn.sanity.io; connect-src 'self' <Preview project>;
worker-src 'self' blob:`. Also exact-Host lock, HTTPS 308, dotfile denial, `-Indexes`, HTML
`no-cache`, hashed assets immutable.

**New in this phase (`8c1fd41e`):** `check:static:selftest` asserts every header above and five CSP
directives with nine mutation proofs. Before this, only noindex and cache lines were asserted, and
`check:security-headers` measures the `next start` server, which is not what Hostinger delivers.

## 3. Secrets and configuration

- `NEXT_PUBLIC_*`: `SANITY_DATASET`, `SITE_URL`, `LEAD_INTAKE_URL`, `BUNDLE_SIZE_PROBE` — none
  secret. Server-only names (`SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `CRON_SECRET`,
  `SLACK_LEADS_WEBHOOK`, `DIRECT_CONNECTION_STRING`, `SANITY_API_WRITE_TOKEN`) are used only in
  server files the static build removes; `build-static.mjs` strips private variables from the build
  environment. No credential found in tracked files (one loopback disposable test-DB password in
  `scripts/check-edge-database.mjs`).
- Scans: `lint:secrets` sweeps `.next/static/chunks`; `check:static:artifact` sweeps `out/` for
  marker names, PEM, `postgres://`, `re_…` and **now `sb_secret_…` (`0784d7d3`)**, plus
  service-role JWT claims. In CI no secret values are supplied, so the `out/` scan is pattern-only.
- This phase never read or copied the owner's `.env.local`; the worktree runs CI-like without
  secrets.
